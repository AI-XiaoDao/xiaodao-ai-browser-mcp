> 本文档面向**用本产品开发/定制 AI 智能体的开发者**。
> 客户入门请看《客户使用手册.md》, 配置接入请看《MCP工具配置说明书.md》。

## 1. 这是什么

「小刀AI智能体定制版 · AI浏览器 MCP」是一套**为定制智能体(Agent)打造的浏览器自动化 MCP 服务**:

- 给你的智能体装上"眼睛和手": 控制真实浏览器(CEF/Chromium 内核)完成
  网页导航、数据采集、自动填表、点击拖拽、截图下载等操作。
- 更进一步的"逆向工具台": JS 逆向 Hook、CDP 断点调试、网络抓包与拦截、
  指纹反检测、工作流编排 —— 一共 **351 个 MCP 工具**。
- **纯本地运行**: 不监听任何端口, MCP 通信只走本机管道; 通过标准 **MCP 协议(JSON-RPC 2.0) over stdio**
  被**任何支持 MCP 的客户端**直接调用 —— Cursor / Claude Desktop / Cline / Windsurf / Codex /
  或你自己写的 Agent, 均使用**同一套 JSON 配置**接入（唯一例外是 Codex: 它读的是 `~/.codex/config.toml` 的 `[mcp_servers]` 段, 见 index.html 的 Codex 页签）。

```
你的智能体(AI 大脑)
      │  MCP 协议 (JSON-RPC 2.0, 仅 stdio 通道)
      ▼
AI-Fbowser-Mcp.exe  ←—— Google Chromium（CEF）内核 + 351 工具
      │
      ▼
真实浏览器窗口 / 网页 / 网络请求
```

> 🪟 **窗口默认隐藏(v3.3.2 起)**: 上图末端那个"真实浏览器窗口"在 stdio 启动后**创建完即隐藏、不占桌面**
> (`mcp_config.json` 的 `start_hidden` 默认 `true`; 命令行 `--visible`/`--show-window` 强制可见、`--hidden` 强制隐藏)。
> 它仍然是**真实**窗口, 只是不可见 —— 绝大多数工具(导航/读页面/执行 JS/抓包/CDP)照常工作。
> **但坐标类输入会受影响**: 窗口隐藏时 `mouse_wheel` / `touch_*` 会**立即失败**、`mouse_move` 会变慢
> (渲染器被浏览器后台化节流) —— 这**不是通道故障**, 别据此判定内核挂了。
> 跑这类用例前先 `browser_show_window {visible:true}`, 用完 `{visible:false}` 收回。
> 点窗口 X 的语义: 默认 `exit_on_window_close: false` = **只隐藏窗口**, 服务继续可用。

## 3. 接入你的智能体

### 3.1 通用接入 —— 所有 MCP 客户端都一样

**不针对任何特定客户端。** 本产品就是一个标准 MCP 服务器, 支持 MCP 的客户端都用**同一套 JSON 配置**接入（Codex 例外: 用 TOML）,
没有客户端专属步骤、也不需要额外插件。

**只有一种接入方式 —— 直连 stdio**:

```json
{
  "mcpServers": {
    "ai-browser": {
      "command": "<本机 exe 真实完整路径 —— 由 --print-config 自动填好>",
      "args": ["--mcp-stdio"]
    }
  }
}
```

> 📌 **别手写路径。** 运行 `AI-Fbowser-Mcp.exe --print-config`（等义 `--dump-config`；双击 exe 也一样）
> 会把**本机真实 exe 绝对路径**填好并打印出上面整段 JSON，直接复制即可。该模式**只打印就退出**：
> 不启动 MCP 服务、不建浏览器、不占桌面 —— 适合装完自检与脚本里生成配置（`--print-config > mcp.json`）。
> 手动拼路径时注意含空格/中文的路径要转义（正斜杠 `/` 或双反斜杠 `\\`）。

> ✅ 不需要 node、不需要端口、不需要 `mcp_bridge.js`、不需要任何环境变量。
> 客户端会自己拉起 exe, 并通过管道与它通信。

### 3.2 程序直连(自己写 Agent 骨架)

用 `spawn` 拉起 exe, 走 **stdin/stdout 管道**收发 JSON-RPC 2.0(每行一帧):

```js
const { spawn } = require('child_process');
const p = spawn('C:/你的路径/AI-Fbowser-Mcp.exe', ['--mcp-stdio']);
const send = o => p.stdin.write(JSON.stringify(o) + '\n');
let buf = '';
p.stdout.on('data', d => { buf += d; /* 按 '\n' 切帧, 逐帧 JSON.parse */ });

send({ jsonrpc: '2.0', id: 1, method: 'initialize',
       params: { protocolVersion: '2025-06-18', capabilities: {}, clientInfo: { name: 'myagent', version: '1' } } });
send({ jsonrpc: '2.0', method: 'notifications/initialized' });
send({ jsonrpc: '2.0', id: 2, method: 'tools/list' });
send({ jsonrpc: '2.0', id: 3, method: 'tools/call',
       params: { name: 'browser_navigate', arguments: { url: 'https://example.com' } } });
```

- **授权**: **无**。本版免费发布, 拉起即可用 —— 不需要传卡密、不需要环境变量、也没有 `AIB-AUTH` 首行握手。
- **没有 HTTP 端点、没有 WebSocket、没有可连的端口** —— 只支持 stdio。

## 4. 开发你的第一个智能体(最小示例)

接上第 3.2 节的管道后:

```js
await call('browser_navigate', { url: 'https://example.com' });     // 打开网页
const text = await call('browser_get_text', { selector: 'body' });  // 取正文
```

**提示词要点**(让 AI 用得稳):

1. 先 `browser_snapshot` 拿页面交互元素清单(带索引), 再用索引点击 —— 成功率最高;
2. 读类工具默认**同步返回**; 慢操作(截图/下载/wait)返回 `task_id`, 用 `mcp_result` 取结果;
3. 填表前先 `browser_get_forms` 了解字段结构, 再 `browser_fill_form` 批量填;
4. 采集多页数据: `browser_scroll_by` → 等待 → 提取 → 循环;
5. 不确定有哪些工具时, 让 AI 先 `mcp_help {query:"..."}` 搜一下, 比让它猜工具名可靠得多。

## 5. 可选: 用 mcp-tools 目录登记你自己的 MCP 工具

> 本节只对**支持"按目录自动注册 MCP 工具"这一约定的宿主**有意义。
> 用 Cursor / Claude Desktop 等通用客户端时**不需要它** —— 直接按第 3.1 节填配置即可。

`mcp-tools\` 是**可选**的扩展目录(代码不写死工具, 目录即清单)。**随包不附带这个目录**, 需要时自行在 exe 同目录创建(或用环境变量 `AI_BROWSER_MCP_TOOLS_DIR` 指定别处), 每个子目录放一个 `tool.json`:

```
mcp-tools\
  (子目录名 = serverName)
  ai-browser\           ← 内置浏览器 MCP
    tool.json
  <你的工具名>\          ← 新建文件夹即可添加自定义 MCP 工具
    tool.json
```

最小 `tool.json`(直接拉起 exe 的工具):

```json
{ "id": "mcp-mytool", "serverName": "mytool", "enabled": true,
  "mode": "stdio", "exe": "我的工具.exe", "args": ["--mcp-stdio"] }
```

**推荐用 `mode: "stdio"`。** 若你的工具是 node 脚本, 请把它写成 **stdio 直通**
(stdin/stdout 转发), 不要再写"桥接到 HTTP 端口"的形态 —— 本产品已无 HTTP 通道。

> 字段归属说明: 本产品侧只读取**子目录名(serverName)**与清单里的 **`enabled`**（`mcp_tools_set` 就是改这个字段）；`id` / `mode` / `exe` / `args` 等由**拉起它的宿主程序**解释，写法以宿主文档为准。

下次启动智能体自动注册; 删文件夹即自动清理条目。

## 6. 工作流编排(免写代码的组合拳)

`workflow_run` 用 JSON 步骤串起多次工具调用:

```json
{ "steps": [
  { "tool": "browser_navigate", "args": { "url": "https://example.com" } },
  { "tool": "browser_get_text",  "args": { "selector": "h1" } }
] }
```

内置样例见安装目录 `workflows\*.json`(`workflow_list` 可列)。

## 7. 开发者实用技巧

- **同步 vs 异步**: 读操作默认一次调用出结果; 大任务可设 `async_only:true` 立即拿回执 —— 但 `browser_navigate` / `back` / `forward` / `reload` 这类"跳过等待"命令**不返回 `task_id`**, 要轮询的是返回了 `task_id` 的那些。完成时服务端会推 `notifications/tasks/status`; 标准查询用 `tasks/get` / `tasks/result`, `mcp_result` 是**兼容保留**的等价入口(按 `request_id` 取)。
- **网络定位问题**: `browser_network {action:list}` 看请求, `browser_network_body` 取响应体, `browser_intercept` 拦改。
- **逆向加密参数**: `browser_reverse_search_script` 找关键字 → `browser_reverse_hook` Hook 函数 → `browser_debugger_*` 下断看现场。
- **防检测**: `browser_antidetect_presets {preset:"full"}` 一键部署; 指纹/UA/时区按需虚拟化。
- **稳定性**: 工具自带线性退避重试 `browser_retry`。
- **多实例**: `browser_create` 建多个浏览器实例并行干活, 用 `browser_id` 指定目标。

## 8. 常见场景速查

| 场景 | 组合 |
|---|---|
| 列表页采集 | navigate → snapshot → 循环{ fill_form/click → extract } |
| 登录后抓数据 | navigate → snapshot → fill_form(账号密码) → click 登录 → extract |
| 验证码/滑块 | 拖动用 `browser_touch_press` → `browser_touch_move` → `browser_touch_release`, 或 `browser_reverse_input_cdp`(`kind:mouse`, `mousePressed/mouseMoved/mouseReleased`)直发 CDP 鼠标事件; 截图交给视觉模型识别 |
| JS 加密逆向 | reverse_search_script → reverse_hook → debugger_flow → 拿明文算法 |
| 定时监控 | `schedule` 工具(once / interval / cron), 或 workflow_run 编排 |
| 多标签并行 | browser_create 多实例 + workflow 分步编排 |

## 9. 授权与安全(开发者须知)

- **本版免费发布, 无需任何激活**: 没有卡密、没有机器码绑定、没有 `license.json`,
  也没有 `--activate-card` / `--check-card` / `--license-status` 这些命令行开关,
  环境变量 `AIB_CARD_CODE` 与 stdio 首行 `AIB-AUTH` 握手**均已移除**。
  (2026-09-16 前的卡密授权系统已整体下线。)
- 程序内部仍保留一项**第三方**授权: FBrowser(CEF) 类库自身的 VIP 注册码(内置常量)。
  那是上游类库的授权凭证, 与用户无关、无需也无法配置。
- **不监听任何端口**, 无网络暴露面; 也不需要配置 api_key 之类的东西
  (`mcp_config.json` 里的 `api_key` / `disable_auth` 已不生效)。
- 浏览器数据在本机 `CacheData\` 下, 清理用 `browser_clear_cache`。

## 附: JSON 封装类速查(2026 升级后)

标准模块的原始 API 与旧 yyjson **同名不同义**, 因此项目提供薄封装, 调用形状与旧代码完全一致(**迁移只改类型名**):

| 旧类型名(已全部替换) | 新类型名 | 说明 |
|---|---|---|
| `YYJSON对象类` / `YYJSON只读对象类` | `MCPJson对象` | 对象节点 |
| `YYJSON数组类` / `YYJSON只读数组类` | `MCPJson数组` | 数组节点 |
| `YYJSON格式化选项` | `MCPJson选项` | `压缩` / `格式化` |
| `YYJSON值类型` | `MCPJson值类型` | `未知0 空值1 逻辑值2 数值3 文本值4 数组值5 对象值6` |

对外方法(与旧 API 同名): `创建自文本` `创建自字节集` `到可读文本` `到字节集` `是否为空` `清空` `成员数`/`取成员数` `加入文本成员` `加入整数成员` `加入长整数成员` `加入小数值成员`/`加入小数成员` `加入逻辑值成员` `加入数组成员` `加入对象成员` `加入成员` `取文本` `取整数` `取长整数` `取逻辑值` `取小数` `取对象` `取数组` `取路径对象` `取路径数组` `成员是否存在` `取所有键名` `删除成员` `取类型` `是否为数值` `是否为逻辑型` `到文本` `到整数` `到长整数` `到小数` `到逻辑值` `创建自文本数据`(文本数组→JSON数组)。

**写新代码建议**: 直接用封装类 + 上面这些方法; 不要直接调用标准模块的 `取对象值/取数组值(出参)` —— 本机不可用。
