# 架构 / Architecture

## 进程与通道
单进程 Windows 控制台程序，**仅 stdio**（--mcp-stdio），不监听任何端口。stdout 只承载 JSON-RPC 协议帧；
所有日志走 **stderr**（默认 GBK，可 AI_BROWSER_MCP_STDERR_UTF8=1 切 UTF-8），并同时落盘到程序目录 mcp_console.log（超 8MB 滚动保留上一份）。

## 并发模型（A9-D1）
- **1 个读线程**：只做「读帧 + 解析 + 入队」；队列为固定容量环形缓冲（256），满时**阻塞入队方**形成背压（宁可让客户端多等，不丢请求）
- **3 个工作线程**：执行工具调用；每轮唤醒检查退出标志
- **读线程快答**（不取协议锁、不等工作线程）：①RPC ping ②全忙(3/3)时 ping 工具降级快答 ③全忙时 **	ools/list** 用启动期预置的只读快照直接答 ④全忙超阈值(默认 8s)对新到的 	ools/call 回**可观测的繁忙拒绝**

## CDP 通道
- 每个域（Runtime/Debugger/Profiler…）未启用时**反应式自动补齐**：命中 gent is not enabled → 补 域.enable → 重试一次 → 经结果对象 uto_prepared 字段**如实上报**（不静默改状态）
- 通道健康度：收到回执（含**带错误体的合法回执**）即刷新；真超时标记不可用并在 5 分钟后自动复探
- 大载荷在 CDP 回调侧**源头封顶**（默认 400KB），避免组装期崩溃

## 帧处理（MCP_Stdio）
自动识别两种帧：官方 Content-Length（CRLF 或仅 LF）与换行分隔的裸行 JSON。已覆盖：管线化、帧体含空白、参数内含字面量 Content-Length:、内嵌 NUL（回 -32700）、CL 声明**偏大/偏小**（显式 -32700 + 优雅退出，不永久挂起）。块读避免大单行请求退化（2MB 单行实测 362ms）。

## 缓存库与自愈
SQLite（mcp_cache.db，WAL）。启动时：①上次非正常退出遗留 -wal/-shm → 隔离三件套并改用全新库；②**真实往返自检**（JS 通路 1+1 必须回 2，并先等主浏览器注册完成，避免把启动期竞态误判为"内容型毒化"）；③隔离产物按**保留最近 3 套**回收（按文件名时间戳排序，非文件时间 —— MoveFileW 保留原时间）。
