# 优势 / Why this server

> 以下每条都能在 docs/VERIFICATION.md（机对机证据）或仓库内代码/文档中找到对应事实；无法验证的卖点一律不写。

## 1) 能力密度：**348** 个工具，一个进程
不止"导航 + 取文本"：内置网络抓取与 **CDP 逆向**（无侵入 Hook、热补丁、精确覆盖率、混淆检测、堆与调用栈）、
调试器全流程、**反检测/指纹**维度、**内核层事件与协议**（证书/下载/右键菜单/自定义 mcp:// 方案/IPC）。多数同类项目只覆盖前两栏。

## 2) 零前置但不"静默改状态"
遇到"域未启用"这类**隐式前置**（Runtime/Debugger 等），服务端会**自动补齐并重试一次**，同时把补过什么
通过回执里的 `auto_prepared` 字段**如实上报** —— 既不让你背一堆前置命令，也不偷偷改环境。

## 3) 错误如实回报，不假装成功
不可序列化的返回值不会被伪造为 `{}`：回执给出**CDP 原文**（如 Object couldn't be returned by value）并注明
"**不会回退重跑**（以免副作用重复）"；通道是否健康、超时是否真用满预算，也都写成可行动的说明。

## 4) 传输层是"做过故障注入"的
自动识别官方 Content-Length（CRLF 或仅 LF）与裸行帧；对**管线化、帧体含空白、参数内含字面量 Content-Length:、
内嵌 NUL、CL 声明偏大/偏小**都给出显式 -32700 或优雅退出，**不会永久挂起**；大单行请求走块读（2MB 实测 362ms）。

## 5) 饱和不再是"全实例卡死"
工作池全忙时，ping、	ools/list 由**读线程直接应答**（实测 	ools/list 从 **11,267ms 降到 94ms**），
第 4 条 	ools/call 得到**可观测的繁忙拒绝**而不是静默排队到客户端超时。

## 6) 会自愈，也有上限
异常退出留下的缓存库残留会被**隔离并换新库**；启动时做**真实往返自检**（且先等浏览器注册完成，避免把启动竞态
误判成"毒化"）；隔离产物按**保留最近 3 套**回收，安装目录不会无限膨胀。

## 7) 可验证，而非"口头承诺"
回归套件（帧族 / 传输 / 工作池 / CDP 诚实性 / 客户端矩阵 / 浸泡）**随仓发布**，一条命令可复跑；
Release 资产带 **MD5+SHA256 清单**，并有 **CI 门禁**按清单逐个重算校验（checksums 作业已实测通过）。

## 8) 部署干净
单进程、**仅 stdio、不监听任何端口**、不依赖 .NET/Java/Python/Node；中英双语文档齐备（快速上手/架构/部署/兼容性/SBOM/已知边界）。
