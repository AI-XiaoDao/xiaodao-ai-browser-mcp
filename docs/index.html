AI浏览器 MCP Server

基于 Google Chromium（CEF）内核的浏览器自动化 MCP 服务。通过标准 MCP over stdio 接入，为 Cursor、Claude Desktop 及任何 MCP 客户端提供 351 个浏览器自动化工具。

概述

AI浏览器 MCP Server 由 MCP 客户端以 --mcp-stdio 自动拉起，不监听任何端口。AI 客户端通过 tools/call 调用 browser_navigate、browser_screenshot 等工具，即可操控内嵌 CEF 浏览器完成自动化任务。

快速开始

解压（无需激活）
本版为免费发布，解压即用：没有卡密、没有机器码、没有 license.json，也没有任何激活命令。双击 AI-Fbowser-Mcp.exe 可查看版权信息与按本机路径生成好的客户端配置。
配置 MCP 客户端
把下方 JSON 填进客户端的 MCP 配置（Cursor：设置 → MCP → 添加服务器）。路径不用手改：下方 JSON 里的 command 只是示意 —— 真正要用的是 双击 AI-Fbowser-Mcp.exe（或运行 AI-Fbowser-Mcp.exe --print-config）按你本机真实路径打印出来的同一段 JSON，直接复制即可。
完全重启客户端
彻底退出再打开（不是重开对话），工具列表即出现 ai-browser。
调用工具
在对话中让 AI 使用 browser_navigate 打开网页；读操作如 browser_get_title 默认 sync-wait 一次返回。
{
  "mcpServers": {
    "ai-browser": {
      "command": "<本机 exe 真实完整路径 —— 由双击 / --print-config 自动填好>",
      "args": ["--mcp-stdio"]
    }
  }
}
上面 command 里的尖括号是说明，不是可用路径。请用 --print-config（或双击）打印出来的那一份，不要手写 D:/你的解压路径 这类占位符。
--print-config 只打印配置就退出：不启动服务、不建浏览器、不占桌面；等义开关 --dump-config，可 > mcp.json 落盘。

架构说明

Cursor / Claude / 任意 MCP 客户端
        │  stdio（逐行 JSON-RPC 2.0）
        ▼
AI-Fbowser-Mcp.exe（MCP_Stdio.wsv 通道 → MCP_Server.wsv 分发）
        │
        ▼
Google Chromium（CEF）浏览器（内嵌）
  • MCP_Stdio.wsv — stdio 通道，逐行 JSON-RPC 收发
  • MCP_Server.wsv — JSON-RPC 分发、sync-wait、batch、工具注册表
  • MCP_Server_Core / Form / VIP / System / Workflow — 模块化工具分派（Core 导航/CDP、Form 填表、VIP 高级功能、System 元工具、Workflow 步骤链）
  • MCP_BrowserEvents.wsv — 网络/控制台/导航 Hook、事件记录
  • MCP_Callbacks.wsv — JS/高级功能异步回调、任务结果存储、DOM 语义失败检测

自有程序同样以 stdio 拉起（spawn）本 exe，参数 --mcp-stdio，无端口可连。

MCP 协议流程

以下消息均在 stdio 通道上以逐行 JSON-RPC 传输，没有 HTTP 端点。

1. initialize

{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","clientInfo":{"name":"my-app","version":"1.0"}}}

2. notifications/initialized

{"jsonrpc":"2.0","method":"notifications/initialized"}

3. tools/list — 获取工具

{"jsonrpc":"2.0","id":2,"method":"tools/list"}

4. tools/call — 调用工具

{"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"browser_navigate","arguments":{"url":"https://example.com"}}}

直接命令（可选）

也可将 method 直接设为工具名，跳过 tools/call 包装：

{"jsonrpc":"2.0","id":4,"method":"browser_get_title","params":{"browser_id":1}}

工具名同时支持 browser.navigate 与 browser_navigate 双路由。

MCP 客户端接入

Cursor、Claude Desktop、Cline、Windsurf、Trae、Cherry Studio、Roo Code、Continue 等任何支持 MCP 的客户端配置方式相同：command 填 exe 路径，args 填 --mcp-stdio。

DeepSeek Harness (DSH) 使用 ~/.dsh/profiles/<profile>/cordis.patch.yml 的 YAML patch；Codex 使用 TOML。DeepSeek 官方聊天端或不提供 MCP 入口的 WorkBuddy 版本无法直接挂载本服务。

{
  "mcpServers": {
    "ai-browser": {
      "command": "<本机 exe 真实完整路径 —— 由 --print-config 输出>",
      "args": ["--mcp-stdio"]
    }
  }
}

不要手填路径：运行 AI-Fbowser-Mcp.exe --print-config（或直接双击 exe），它会按你本机的真实路径打印好上面这段 JSON，整段复制即可。上面 <…> 里是说明文字，不是可用路径。

拿到路径后要手改时：正斜杠 / 或双反斜杠皆可，再彻底退出并重启客户端。

不需要 node、不需要端口、不需要任何环境变量；程序由 MCP 客户端自动拉起。当前构建仅 stdio，不支持远程服务器部署。

Sync-Wait / 异步任务

v2.5 起，常用读操作默认 sync-wait：在同一次 tools/call 内轮询 async 任务并返回结果，响应可含 "_sync_waited":true。无需客户端二次 mcp_result。

参数说明
（默认）白名单工具自动 sync-wait
async_only: true强制纯异步，立即返回 task_id
sync_wait: true对非白名单工具也启用 sync-wait
max_ms: N自定义等待超时（毫秒）

默认 sync-wait 白名单（完整）：get_title、evaluate、execute_js、console_eval、get_url、get_id、status、is_loading、is_muted、can_navigate、get_zoom、loading_info、popup_info、window_info、dom_query、dom_set_value、dom_click、dom_inner_html、dom_checked、dom_selected、dom_rect、get_frames、frame_names、fill_exists、fill_attr_get、fill_set_value、fill_click、get_cookies、get_all_cookies、screenshot、get_source、cdp_call/cdp/cdp_event/event、dom_select/extract/view_source/scrape、vip_dom_get_document/vip_dom_search/reverse_cookie_sources、debugger 全套；navigate/reload 按 wait_for_load，get_text/dom_get_html 仅当传入 selector。

batch：默认对子命令自动跟随 async 结果；子命令失败时外层 success:false；batch 级 async_only:true 关闭跟随。

纯异步轮询

非白名单或显式 async_only:true 时，返回 task_id（格式 task_<毫秒>_<盐>_<计数>），通过 mcp_result 查询：

{"jsonrpc":"2.0","id":5,"method":"tools/call","params":{"name":"mcp_result","arguments":{"request_id":"task_xxx"}}}

工作流 workflow

将多步 MCP 调用编排为 JSON 步骤链，存放于 exe 同目录 workflows/（环境变量 AI_BROWSER_WORKFLOWS_DIR 可覆盖）。

工具说明
workflow_list列出 workflows/*.json
workflow_get参数 name 或 file，返回定义 JSON
workflow_run参数 name / file / definition / steps；步骤默认 sync-wait
workflow_stop中止运行中工作流；空闲调用清除停止标志

加载优先级：name/file 优先读磁盘文件；内联 definition 仅作 fallback（空 definition:{} 不会拦截文件加载）。

步骤 JSON 示例

[
  { "tool": "ping", "args": {} },
  { "delay_ms": 300 },
  { "tool": "browser_navigate", "args": { "url": "about:blank" } },
  { "tool": "browser_wait", "args": { "what": "load_end", "max_ms": 5000 } }
]

每步可选 on_error："stop"（默认）或 "continue"。内置示例：hello.json、ping_navigate.json。

事件监控与数据采集

browser_collect 统一入口：网络/控制台/场景预备/事件 Hook。查询导航等事件用 browser_event。

场景预备

{"name":"browser_collect","arguments":{"action":"reverse_prepare","clear":true}}
{"name":"browser_collect","arguments":{"action":"debug_prepare"}}
{"name":"browser_collect","arguments":{"action":"automation_prepare"}}

事件监控

{"name":"browser_collect","arguments":{"action":"event_all_enable"}}
{"name":"browser_event","arguments":{"event_type":"navigate"}}

支持 event_load_enable、event_resource_enable、event_dialog_enable 等单项；event_all_disable 批量关闭。详见 tools/list 动态清单与 docs/ 目录下的既有文档。

默认开启：载入 / 生命周期 / 标题 / 下载 4 类；进度 / 资源 / 对话框 / 全屏 / 图标 / 查找 / 框架 / 键盘焦点 / 应用事件默认关闭。event_all_enable 开启 28 项（13 事件族 + 3 日志 + 12 扩展族），与 browser_kernel_events_all 的集合完全一致；event_all_disable 逐项对称关闭。如需精细控制，仍可用单项 event_resource_enable / event_focus_enable 等。

注意：本服务不提供 Chrome 原生 /devtools/browser/{id} WebSocket 代理。CDP 请使用 MCP 工具：
  • browser_cdp_call — 发送 CDP 命令
  • browser_cdp_event — 监听 CDP 事件

配置文件 mcp_config.json

放在 exe 同目录，启动时自动加载。完整说明见 MCP工具配置说明书.md。

{
  "enable_network_log": true,
  "enable_console_log": false,
  "enable_response_cache": false,
  "network_log_max_bytes": 262144,
  "auto_download_save": true,
  "auto_dismiss_js_dialog": false,
  "window_topmost": true,
  "start_hidden": true,
  "exit_on_window_close": false
}

start_hidden（默认 true）= 主窗口创建后立即隐藏、不占桌面，写 false 才保持可见；exit_on_window_close（默认 false）= 点窗口 X 只隐藏窗口、MCP 继续跑，写 true 才随 X 整体退出。两者都由命令行 --hidden / --visible 覆盖。

文件里若出现 port / bind_address / disable_auth / api_key，那是早期 HTTP 模式的遗留：现行版本不监听端口，这些键读取但无实际作用（bind_address 非空只会打印一条安全警告），可直接删除。

⚠ 但 rate_limit_per_minute 不在其列 —— 它至今仍然生效：0（默认）= 不限速；>0 时按每分钟上限限流，超限请求会以 -32000「请求过于频繁」被拒（附 Retry-After）。

常见问题

客户端看不到 ai-browser

确认 MCP 配置里 command 是实际 exe 路径、args 填 --mcp-stdio，并彻底退出重启客户端（不是重开对话）。

需要卡密 / 提示激活吗？

不需要。本版为免费发布，程序内没有任何激活前置条件，也没有 `--activate-card` 之类的命令。

browsers: 0

主窗口浏览器尚未创建，稍等几秒重试，或让 AI 调用 browser_create 主动创建。

工具返回 task_id 但 mcp_result 为空

若未设 async_only:true，白名单工具应已 sync-wait 直接返回。纯异步任务可能仍在执行，稍等后重试。

程序怎么启动、怎么退出？

由 MCP 客户端自动拉起、随客户端退出，不需要手动双击。要单独退出可让 AI 调用 browser_shutdown。

浏览器窗口在哪？我怎么看不到？

这是正常的 —— 本版默认隐藏窗口（mcp_config.json 的 start_hidden 默认为 true）：主窗口创建后立即隐藏、不占桌面，服务在后台照常干活。

  • 想让它一直显示：启动时加 --visible（等义 --show-window），或把配置里 start_hidden 写成 false。
  • 只是想看一眼：让 AI 调用 browser_show_window {visible:true}；{visible:false} 收回。
  • 手动关掉窗口：默认只隐藏窗口（exit_on_window_close 默认 false），桌面立刻干净而 MCP 继续可用。想「点 X = 整个退出」就把 exit_on_window_close 写成 true。
  • 命令行优先级：命令行开关 > mcp_config.json > 内置默认（隐藏）。
窗口隐藏时坐标类输入（mouse_wheel / touch_*）会自动临时显示窗口并重试一次（v3.3.2 起自愈，回包会标注），闲置 8 秒后自动收起；需要持续可见请先 browser_show_window {visible:true}。mouse_move 在后台可能变慢，属节流而非通道故障。

文档打不开

直接打开 exe 同目录 docs/ 下的 Markdown 文件。程序不监听端口，不提供网页。

页面卡住 / MCP 超时

多见于 debugger 暂停未恢复。调用 browser_debugger_resume，或调用 browser_restore_gui、browser_reload。

POST 加密参数扫描失败

先解除 debugger 暂停，再用 browser_collect reverse_prepare + browser_inject persist Hook 扫描。勿并行跑多个 MCP 脚本。
