# 路线图 / Roadmap（已知边界的处置计划）

| 已知边界 | 类型 | 计划 | 验收标准 |
|---|---|---|---|
| **未代码签名** | 外部依赖 | 见 [CODE-SIGNING.md](CODE-SIGNING.md)：**需要证书持有方执行**；仓库侧已备好流程与 CI 接入位 | 产物 `signtool verify /pa` 通过，且发布说明记录证书主体/指纹 |
| **缓存库"内容型"毒化根因未定** | 产品修复 | 3.3.4 计划：启动自检改为**确定性判据** —— 先跑 `PRAGMA integrity_check`：① 不通过 ⇒ 判定库损坏并隔离换新；② 通过但 JS 通路异常 ⇒ **如实报告"JS 通路异常、缓存库完整"**，不再归因毒化 | 构造"库完整但 JS 异常"与"库损坏"两种场景，断言分别走"如实报告"与"隔离换新"两条分支；34 项回归全过 |
| **全忙期 `initialize`/`workflow_stop` 仍入队** | 产品修复 | 3.3.4 计划：① 读线程**吸收无 id 的通知**（`notifications/*`，无需工作线程）；② `initialize` 采用与 `tools/list` 同款**启动期预置快照**（协商版本不一致时回落入队） | 饱和期发 `notifications/initialized` 与 `initialize`，断言前者不被排队、后者毫秒级返回或明确回落；非饱和期行为零变化 |
| **默认 stderr 混合编码（项目 GBK + CEF UTF-8）** | 已缓解 | 3.3.3 已提供 `AI_BROWSER_MCP_STDERR_UTF8=1` 统一切 UTF-8；**默认保持 GBK 以兼容中文控制台** | 已实测：UTF-8 模式替换符 0 |
| **GUI 客户端矩阵未实测** | 待用户环境 | 需在装有 Claude Desktop / Cursor / Trae 的机器上用 `--print-config` 配置实测；协议级矩阵已 7/7 | 至少 2 个真实客户端完成握手 + `tools/list`(348) + 一次工具调用 |
| **浸泡为冒烟级（6 分钟）** | 待补 | 跑 1–2 小时长浸泡并对比前后半段 p95 是否退化 | 无回包 0、工作集/句柄无单调增长、后半段 p95 ≤ 前半段 1.5× |

> 纪律：上表**只写可验收的动作**；任何一条完成后，本表与 [KNOWN-LIMITS.md](KNOWN-LIMITS.md) 同步更新。
