# 路线图 / Roadmap（已知边界的处置计划）

| 已知边界 | 类型 | 计划 | 验收标准 |
|---|---|---|---|
| **未代码签名** | 外部依赖 | 见 [CODE-SIGNING.md](CODE-SIGNING.md)：**需要证书持有方执行**；仓库侧已备好流程与 CI 接入位 | 产物 `signtool verify /pa` 通过，且发布说明记录证书主体/指纹 |
| **缓存库"内容型"毒化根因未定** | 产品修复 | **已落地（v3.3.5）**：启动 `PRAGMA quick_check` + 健康库保留/checkpoint，仅损坏或打不开时隔离重建；真实往返自检作为内容型异常兜底。根因仍未定位 | 已覆盖"健康库强杀残留不误隔离"与"损坏库隔离换新"；内容型毒化仍缺可外部复现的触发条件 |
| **全忙期 `initialize`/`workflow_stop` 仍入队** | 产品修复 | 后续计划（未排期）：① 读线程**吸收无 id 的通知**（`notifications/*`，无需工作线程）；② `initialize` 采用与 `tools/list` 同款**启动期预置快照**（协商版本不一致时回落入队） | 饱和期发 `notifications/initialized` 与 `initialize`，断言前者不被排队、后者毫秒级返回或明确回落；非饱和期行为零变化 |
| **默认 stderr 混合编码（项目 GBK + CEF UTF-8）** | 已缓解 | 3.3.3 已提供 `AI_BROWSER_MCP_STDERR_UTF8=1` 统一切 UTF-8；**默认保持 GBK 以兼容中文控制台** | 已实测：UTF-8 模式替换符 0 |
| **GUI 客户端矩阵未实测** | 待用户环境 | 需在装有 Claude Desktop / Cursor / Trae 的机器上用 `--print-config` 配置实测；协议级矩阵已 7/7 | 至少 2 个真实客户端完成握手 + `tools/list`(351) + 一次工具调用 |
| **浸泡为冒烟级（6 分钟）** | 待补 | 跑 1–2 小时长浸泡并对比前后半段 p95 是否退化 | 无回包 0、工作集/句柄无单调增长、后半段 p95 ≤ 前半段 1.5× |

> 纪律：上表**只写可验收的动作**；任何一条完成后，本表与 [KNOWN-LIMITS.md](KNOWN-LIMITS.md) 同步更新。
